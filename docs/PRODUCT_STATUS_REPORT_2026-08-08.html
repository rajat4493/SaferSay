SaferSay

Product Status Report

Prepared for the CEO and Product Owner · 8 August 2026

"Culture Amp's trust guarantee, Officevibe's price and simplicity — built for the 10–60 person company neither is built for."

Bottom line

The confidential-survey product works end to end today: a company can sign up, upload employees, launch a survey, and get a suppressed report once five people have answered — and the guarantee that promise depends on, that identity and answers can never be joined, even by us, is real and passes its own test suite on every run. What it can't do yet is take anyone's money or send a real invite email to anyone but its own developer. Closing those two gaps, plus a short list of production-hardening items below, is what stands between "works in a walkthrough" and "safe to sell."

01

What's complete against the vision

  • DoneConfidentiality architecture: identity and response data live in separate database schemas with no foreign key or join path between them. This is tested automatically on every check, not just documented.
  • DoneMinimum group size floor — reports can never unlock below 3 respondents, enforced on the server regardless of what any screen tries to send.
  • DoneReal multi-tenant sign-in via Google and Microsoft, with a workspace created automatically on first login. No password to manage.
  • DoneFour working roles, all reachable through the product itself as of this build — HR Admin, Survey Creator, Viewer, and Employee. A workspace owner can now invite a teammate by email and role directly; that path didn't exist before this build, and every account used to become an HR Admin regardless of who signed up.
  • DoneThe full survey lifecycle — build from a template, customize questions, send invites, watch results unlock — works as one continuous flow, plus a single smart "send" action that replaced a confusing seven-button panel.
  • DoneCSV employee import with row-level validation.
  • DoneA separate Owner console — every tenant's plan, health, team, and support history in one place, walled off from any tenant's actual survey content.
  • DoneA guided first-run experience — a new workspace now sees one clear next step at a time (load people → create a survey → send it) instead of an empty page.
  • DoneDeployed and live, on a push-to-deploy pipeline exercised repeatedly and reliably this build.
02

What's working right now

Verified against the live database this build, not just shipped and assumed.

  • VerifiedThe complete real-world path: new workspace → CSV import → survey created → tokens issued → invite queued → Owner entering and leaving a tenant's workspace → a teammate invited, accepting, and landing with exactly the access their role allows.
  • VerifiedThe confidentiality test suite passes on every run — the one guarantee that must never have an exception, and doesn't.
  • VerifiedThe Owner layer's block on reading any tenant's response content is real and explicit in code — entering a tenant's workspace gives operational visibility only (plan, headcount, activity), never survey answers, confirmed by reading the guard directly.
03

What's not working

  • BlockedReal invite emails. Resend is connected, but the sending address is still the free shared sandbox address, which the product's own safeguard correctly refuses to use in production. Every invite sent today can only reach one inbox — the developer's own. A verified company sending domain (a DNS task measured in days, not an engineering task) is required before any real pilot can send a single invite.
  • Not connectedTaking payment. There's no Stripe integration yet — no checkout, no webhook. The billing screens that exist are honest placeholders, not broken features pretending to work.
  • Not configuredPrivacy contact address. The privacy notice and DPA pages don't have a live contact wired in — a small fix, but it's on the product's own list of things required before it calls itself production-ready.
  • Operational riskLocal development this build ran against the same database real customers' data will live in — there's no separate staging environment. Several test accounts had to be created and then deleted as a direct result. Not a customer-facing bug, but a real risk every time anyone tests locally.
  • MinorTwo small rough edges inherited from before this build: an occasional harmless duplicate-login error in local dev-mode sign-in only (self-recovers, doesn't touch real customer sign-in), and an unconfirmed bug in the analytics event that records whether an invite batch was actually queued.

04

What's missing, in build order

Closest — needed before the first paying, non-hand-held customer
  • P0A verified email-sending domain for Resend (days, not sprints).
  • P0Stripe checkout, webhook handling, and persisted billing state.
  • P0A live privacy contact address.
  • P0Proof that tenant isolation holds under the database's own enforcement, not just application code. The restricted database role is already configured in production — but the automated tests that prove it actually blocks cross-tenant access don't run anywhere yet; there's no CI, and they're skipped by default locally. This should be run for real before the first paying customer, not assumed.
Next — needed before opening the product to self-serve signups
  • P1Automated checks on every change — lint, tests, build, migration safety. Every one of those checks this build ran by hand.
  • P1Basic error monitoring. Right now, if something breaks for a real customer, nobody finds out unless the customer says so.
  • P1A security hardening pass — rate limiting, response headers, secret rotation, and a known timing-comparison issue in the sign-in middleware.
  • P1Something for the Viewer role to actually do. It can now be invited and correctly sees only what it should — but there's still no audit-log screen for it to look at, which is the entire point of a read-only Viewer.
  • P1Choosing which employees receive a given survey. Today every survey goes to everyone active; there's no "select recipients" step.
  • P1A real PDF export of results — today it's CSV only.
Not urgent yet — and the roadmap already agrees
  • P2Importing an org chart directly from Google or Microsoft — today it's sign-in only, not a directory sync.
  • P2Automated data retention and deletion — today it's an export button and an email link to a human.
  • P2The confidential-disclosure / grievance channel — designed, not built.
  • P3AI-generated interpretation of results — deliberately gated until we know people will pay for the core product first.
05

Deliberately not built — don't mistake these for gaps

  • By designDepartment- and manager-scoped report views. The plan always called for these after the org-level version, not instead of it.
  • By designA "this is not anonymous" survey mode, designed to be architecturally impossible to build carelessly, on purpose. When it ships, it will be a clearly separate mode — never a toggle on the confidential one.
  • By designAny enterprise-style permission matrix beyond the four roles above. Not asked for yet.

Three small things — a verified sending domain, a Stripe integration, and proof the database's own isolation guarantee actually holds — separate a real working product from one that's safe to put a paying customer's name on.
